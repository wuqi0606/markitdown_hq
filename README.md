# MarkItDown HQ — Dify 插件使用说明

基于微软 [MarkItDown](https://github.com/microsoft/markitdown) 0.1.8 的 Dify 文档处理插件，  
将 PDF、Word、Excel、PPT、HTML 等文档转换为干净的 Markdown，供知识库分段与向量化使用。

## 解决的核心问题

**标题层级丢失。** 不少 Word 文档的章节标题用的是**普通加粗段落**，  
不是「标题1/2/3」样式。MarkItDown 靠样式映射生成 `#`，样式没标就全丢了——  
转换后父子分段的 `\n#` / `\n##` 分隔符完全失效。

标题补齐已内置（`restore_headings` 参数，默认开启）。层级**按文档实际出现的编号形态动态映射**：  
文档同时出现「一、」和「1、」时，「一、」判 H1、「1、」判 H2；只有「1、」时判 H1。  
识别的编号形态：`第x章`、`一、`、`1、`、`附件x`、`（一）`、`（1）`。  
以分号/句号/逗号结尾的行视为正文不提升；冒号结尾的短行（如「评分标准：」）视为标题。

## 与插件市场版 `yevanchen/markitdown` 的区别

|               | 市场版                    | 本插件                            |
| ------------- | ---------------------- | ------------------------------ |
| MarkItDown 版本 | 0.0.2a1                | **0.1.8**（当前稳定版）               |
| PDF 支持        | 依赖未声明，PDF 常失败          | `markitdown[docx,pdf]`，PDF 已实测 |
| 标题层级          | 不处理，丢失后无法分段            | **内置补齐**                       |
| PDF 页眉页脚      | 不处理，混入正文               | **内置清除**                       |
| 噪声清洗          | 无，输出原样返回               | base64 图片 / 空表格行 / 目录残留        |
| 旧版 .doc 识别    | 报 `BadZipFile`，错误信息不可读 | 按文件头识别，输出明确指引                  |
| 多文件           | 拼接为分隔文本                | 逐份处理，失败项单独列出                   |

## 安装

插件 → 安装插件 → **通过 GitHub**：

1. 仓库填：`https://github.com/wuqi0606/markitdown_hq`
2. 版本选最新 tag，包文件选 `markitdown_hq.difypkg`
3. 安装

## 在 Knowledge Pipeline 中的接法

```
FILE  →  MarkItDown HQ  →  Parent-child Chunker  →  Knowledge Base
```

### MarkItDown HQ 节点参数

| 参数              | 值         | 说明                                      |
| --------------- | --------- | --------------------------------------- |
| 文件              | 绑定数据源输出   | 必填                                      |
| 清除转换噪声          | **是**     | 知识库场景务必开                                |
| **补齐标题层级**      | **是**     | **知识库场景必须开**，否则父子分隔符失效                  |
| **清除 PDF 页眉页脚** | **是**     | PDF 源文件必开，清页眉页脚页码                       |
| 页眉页脚特征词         | 公司名等，逗号分隔 | 额外补充的识别词。内置特征词（密级/编号/保密标识等）始终生效，填写后合并使用 |
| 添加元数据前置信息       | 否         | 引用显示的是文档名，一般不用                          |
| 保留内嵌图片          | **否**     | 知识库场景务必关                                |

### Parent-child Chunker 参数

**父分段**

- Parent Mode：`Paragraph`
- Parent Delimiter：`\n# `
- Parent Max Length：`1200`

**子分段**

- Child Delimiter：`\n## `
- Child Max Length：`400`

> 原文档没有二级标题时，子分隔符不生效，会退化为按最大长度切分，  
> 不影响使用，只是子段语义边界弱一些。

## 已知限制

- **旧版 `.doc`（Word 97-2003）不支持**。即使后缀是 `.docx`，若文件头是 `D0 CF 11 E0`  
  则无法解析，需先用 Word 另存为真正的 `.docx`。插件会在输出开头的  
  \`\` 注释里明确列出。
- 图片被清除后，正文里「如下图所示」这类指代会失去配图。如需保留图片，  
  开启 `保留内嵌图片`——但知识库场景下 base64 会严重损害向量化质量。
- 目录页残留按「`一、 xxx 3`」和 `[标题](#锚点)` 两种形态清理。若你的文档  
  目录格式特殊，可能漏清，检查方式：转换后搜索输出里是否还有带页码的章节标题。
- **PDF 页眉页脚按「重复即页眉」启发式判定**：短行重复出现 ≥2 次且含特征词才删。  
  特征词 = 你在「页眉页脚特征词」参数里填的词（如公司名）+ 内置通用词  
  （密级标识、文件编号、保密标识等）。页码按「距最近已删页眉 ≤3 行」判定。  
  如果只靠内置特征词删不干净，把公司名填进参数即可。
- **PDF 表格会被打散成断裂单元格**，例如  
  `| （内部使用 | 注意保密） |     |`。这是 PDF 无表格结构的固有问题，  
  本插件无法还原。若某份 PDF 的表格内容重要，建议改用 docx 版或人工校对。
